## Лабораторная работа 1: Классы - Реализация объектной модели данных и unit-тестов
Описание предметной области
Реализована объектная модель для поликлиники, в которой присутствуют три основных сущности:

Пациент(Patient) - эта сущность характеризуется следующими данными: номером паспорта, ФИО, полом, датой рождения, адресом, группой крови, резус фактором и контактным телефоном.
Доктор(Doctor) - эта сущность характеризуется следующими данными: номер паспорта, ФИО, год рождения, специализацию, стаж работы.
Запись на приём (Visit) - эта сущность характеризуется следующими данными: пациент, доктор, дата и время приема, номер кабинета, а также индикатор того, является ли прием повторным.
Выполненные задачи

### 1. Модель данных
Создана полная объектная модель с использованием enum-типов:

- Gender - пол пациента (мужской, женский);
- BloodGroup - группа крови пациента (I, II, III, IV);
- RhFactor - резус фактор пациента (положительный, отрицательный);
- Specialization - специализация доктора, она может быть: Therapist, Surgeon, Cardiologist, Neurologist, Pediatrician, Dentist, Ophthalmologist, Dermatologist, Orthopedist;

### 2. Тестовые данные
Создан класс PolyclinicFixture содержащий:
- 10 пациентов
- 10 докторов
- 14 записей на приём

### 3. Unit-тесты
Реализованы все требуемые тесты:

* CountOfDoctorsWithWorkExperienceMoreOrEqual10Years - тест для вывода информацию о всех врачах, стаж работы которых не менее 10 лет.
* AllPatientsToDoctorOrderedByName - тест для вывода информацию о всех пациентах, записанных на прием к указанному врачу, упорядочить по ФИО.
* CountOfRepeatVisit - тест для вывода информацию о количестве повторных приемов пациентов за последний месяц.
* AllPatientsOlder30YearsToSomeDoctorsOrderedByBirthday - тест для вывода информацию о пациентах старше 30 лет, которые записаны на прием к нескольким врачам, упорядочить по дате рождения.
* AllVisitForLastMonthInSelectedCabinet - тест для вывода информации о приемах за текущий месяц, проходящих в выбранном кабинете.

## Результат
Создана объектная модель предметной области с комплексными unit-тестами, покрывающими все требования задания.

# Лабораторная работа 2-3: "Сервер" И "ORM"

## Задания
Во второй лабораторной работе необходимо реализовать серверное приложение, которое должно: - Осуществлять базовые CRUD-операции с реализованными в первой лабораторной сущностями - Предоставлять результаты аналитических запросов (раздел «Unit-тесты» задания)
Хранение данных на этом этапе допускается осуществлять в памяти в виде коллекций.

В третьей лабораторной работе хранение должно быть переделано c инмемори коллекций на базу данных. Должны быть созданы миграции для создания таблиц в бд и их первоначального заполнения.
Также необходимо настроить оркестратор Aspire на запуск сервера и базы данных.

# Лабораторная работа 4: "Инфраструктура" - Реализация сервиса генерации данных и его интеграция с сервером

## Результат

В четвертой лабораторной работе был создан сервис *Generator*, который генерирует контракты с визитами пациентов в поликлинику. Эти контракты далее передаются в сервер и сохраняются в бд.
Реализован генератор данных для *VisitGenerator* в сервисе Generator.
По заданию используется броккер сообщений Kafka в сервисе Generator.
Для "Кафки" были реализованы продюсер *KafkaProducer* в сервисе Generator  для отправки пакетов DTO Визитов.
А также консьюмер *KafkaConsumer* в Api, принимающий сообщения из Kafka и передающий их на обработку.
Также добавлен в конфигурацию Aspire запуск генератора и брокера сообщений.
